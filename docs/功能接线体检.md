# AIYview 功能接线体检

> 时间：2026-11-15 · 范围：`app/src`（主进程 / core / 渲染层）、`app/tests`、仓库文档
> 方法：通道三方对齐扫描（主进程 `handle()` ↔ preload 白名单 ↔ 渲染层调用）、模块引用图、settings 键读写对照、运行态 DOM 探针（release v3.0 / 真实图库 526 张）

## 结论

后端（主进程 + core）的实现覆盖率明显高于界面：**有 15 处「代码写了但用户用不到」**，其中 6 处是真功能缺失（不是 bug，是没接线），3 个模块是纯死代码，6 处是「界面看着正常、实际只做了一半」的隐患。没有 TODO/FIXME 标记，所以这些问题不会在源码里自曝。

---

## A. 明确没接线：功能写了，界面上没有入口

### A1. 文件名搜索 + 分级上限过滤 —— 状态和 SQL 都齐了，就是没有输入框

- `src/renderer/store.jsx:27-28` 定义 `ageMax` / `nameLike` 两个筛选状态，`store.jsx:207-214` 每次都把它们送进 `browse:page`；
- `src/core/db/imageRepository.cjs:120-128,136-139` 对应 `age_level < @ageMax` 与 `file_name LIKE @nameLike`，`ageOnly`、`hideRejected` 也各有一套谓词；
- 但 `setAgeMax` / `setNameLike` **只在 store 里被导出，全项目没有任何组件调用**（grep 结果：只有 store.jsx 自己）。
- 运行态实测：整个界面只有 2 个输入框，占位符分别是「搜索文件夹...」「搜索或创建标签」，**没有文件名搜索框**。

结论：想在 500+ 张图里按名字找一张，只能滚。

### A2. 多图库只能显示第一个，切不了也删不掉

- 后端 `library:list` / `library:register` / `library:remove` 齐全（`services/libraryPicker.cjs:35-52`）；
- `store.jsx:166-172` 初始化时取 `res.data[0].id`，之后再没换过；
- `actions.removeLibrary`（`store.jsx:289-293`）定义了，但没有任何 UI 调它；
- `Sidebar.jsx:130-140` 只渲染当前这一个库。

结论：加第二个文件夹时（`library:pick` 一次性注册并扫），界面上等于只剩第二个库，想回第一个没有入口。

### A3. 提示词库是「只能看和复制」的半成品

- 后端 5 个通道：`prompt:save` / `prompt:save-manual` / `prompt:get` / `prompt:update` / `prompt:remove`（`services/promptLibrary.cjs:13-47`）；
- 渲染层只用了 `prompt:list` 和 `prompt:save`（`BottomBar.jsx:128,164-170`、`Viewer.jsx:171-175`）；
- 面板里每行只有一个「复制」按钮，**不能改标题/备注、不能删、不能手写一条新提示词**。

### A4. 标签只能加，不能减，也看不到某张图已有标签

- 后端有 `tag:of-image`（查图上的标签）和 `tag:detach`（移除标签）（`services/tags.cjs:21,30`）；
- 渲染层只用 `tag:suggest` / `tag:attach` / `tag:get-or-create`（`TagPanel.jsx:17,24,41`、`Sidebar.jsx:225`）；
- 结论：误标一个标签后，界面里没有撤销的路径；也看不到「这张图现在有哪些标签」。

### A5. 标签字典导入 / CSV 标签导入：只有 IPC，没有入口

- `tag:import-dictionary`（读 `selected_tags.csv` 灌中文名/分类/权重，`services/tagger.cjs:202-224`）、`tag:import-csv`（`services/tags.cjs:11-17`）都已实现；
- 渲染层零调用；
- **`项目交接报告_1.0.md` 把「M4 标签字典导入」列为已实现** —— 实际只有后端，新用户装完没有任何地方能点。

连带影响：不导入字典，自动打标出来的标签就没有中文名，`tag:suggest` 的中文联想（`TagPanel.jsx` 依赖 `nameZh`）形同虚设。

### A6. 批量重命名：实现完整 + 有单测，零接线

- `src/core/legacy/batchRename.cjs`（7.6 KB，含占位符解析、冲突处理）+ `tests/unit/batchRename.test.mjs`；
- 主进程没有任何 `handle()` 调它，渲染层也没有任何入口（grep `batchRename` 在 `src/renderer` 为 0 命中）。
- 结论：**功能存在，但用户永远触发不到**。

## B. 界面上「看着正常」，其实只做了一半

### B1. 「共 N 张」显示的是已加载数，不是总数

- `ImageArea.jsx:272`：`共 {items.length} 张` —— 这是当前已翻出来的条数；
- 真正的总数通道 `browse:count`（`services/browse.cjs:30-32`）**渲染层从未调用**；
- 实测：底部写「共 120 张」，`browse.count` 返回 **526**。滚到底才出现，数字误导。

### B2. 打完标不刷新标签栏

- 主进程会广播 `tags-updated`（`services/tagger.cjs:161`），preload 白名单里也有这个事件（`preload.cjs:26`）；
- 渲染层只订阅了 `scan:progress` / `browse:changed` / `tag:progress`（`store.jsx:240-246`），**`tags-updated` 无人订阅**；
- 结论：自动打标跑完，侧栏的标签列表和计数停在旧值，必须手动刷新/切库才更新。

### B3. 文件监听扫到新图，界面不会自己更新

- `services/scanner.cjs:64-93` 每次扫描后 `watchLibrary()` 起一个 chokidar，变化后自动重扫并广播 `browse:changed`；
- 渲染层这句订阅是**空的**：`store.jsx:242` `on('browse:changed', () => { /* 保持列表稳定 */ })`；
- 这符合「排序冻结」的约定，但代价是「丢张新图进 output，界面不会自己出现」——用户仍要点右上角重新扫描。

### B4. 回收站过期记录永不落库清理

- `delete:sweep` → `sweepExpired()`（`services/trash.cjs:89`、`core/db/deletionRepository.cjs:56-61`）已实现，**没有任何调用方，也没有定时器**；
- 列表靠 `expires_at > now` 过滤（`deletionRepository.cjs:40-47`），所以界面看不出坏；
- 实际后果：`deletions` 表里 pending 记录只进不出，越积越多（每次删图都写一条）。

### B5. 文件监听永不停止

- `scan:watch-stop`（`services/scanner.cjs:53-60`）无任何调用方；
- 每扫一次库，若该库还没有 watcher 就新建一个，移除图库时也不回收 → chokidar 实例跟着库数只增不减。

### B6. 缩略图缓存看不见也清不掉

- `thumb:cache-stats`（`services/thumbs.cjs:125`）已实现（缓存条数/占用），**只有开发探针 `devHooks.cjs:113` 在用**；
- 实测缓存目录已经 30 MB+，界面里没有任何「缓存占用/清理」入口。

### B7. `uiScale` 只能改数据库

- `main.cjs:87-108`：启动时读 `settings.uiScale`，默认 1.5；注释写着「可在设置里改 uiScale」；
- 全项目没有写这个键的 UI（实测 `settings.get('uiScale')` 返回 `null`，一直走默认值）；
- 结论：想改界面缩放只能手改 SQLite，注释与实际能力不符。

### B8. 右键没有任何菜单

- `Thumb.jsx:14,67` 声明了 `onContext` 钩子并绑 `onContextMenu`；
- `ImageArea.jsx:259-265` 渲染 `<Thumb>` 时**没传 `onContext`**；
- 结果：右键点了完全没反应（钩子是空壳）。

### B9. 打标状态通道闲置

- `tag:status`（`services/tagger.cjs:197-201`，返回 running/cancelled/progress）无人调用；
- 界面进度只靠 `tag:progress` 事件 + 调用返回值，切窗口/重开时拿不回来「现在跑到第几张」。

## C. 死代码（有实现、有单测、零引用）

| 模块 | 大小 | 现状 | 影响 |
| --- | --- | --- | --- |
| `src/core/legacy/batchRename.cjs` | 7.6 KB | 只有 `tests/unit/batchRename.test.mjs` 引用 | 批量重命名功能等于不存在（见 A6） |
| `src/core/legacy/searchIndex.js` | 5.6 KB | 只有单测引用 | 自然排序 + 网格内模糊过滤未接线 |
| `src/core/legacy/ratingStore.cjs` | 4.7 KB | 只有单测引用 | 旧版 JSON 分级存储；当前分级已走 SQLite（`image:age`），属遗留 |

`searchIndex.js` 的连带后果最实际：它的 `naturalCompare` 注释明确写着「`img_2.png` 会排在 `img_10.png` 后面」这个 upstream 缺口，而名称排序现在就是纯 SQL 字典序（`imageRepository.cjs:160` `ORDER BY rel_path`），**这个缺陷至今存在**。

## D. 纯「死通道」（注册了、界面永远不需要）

`image:dimensions`（`browse.cjs:53`，主进程内部另有 `setDimensions` 调用，通道本身无人用）· `app:info` · `db:status` · `settings:all` · `library:register`（只走 `library:pick` 这一条）· `scan:status` · `tag:search`（侧栏是在本地过滤 `tag:top` 的前 40 个，所以只能搜到这 40 个）

这些不影响使用，但会让 preload 的白名单看起来比真实能力大。
